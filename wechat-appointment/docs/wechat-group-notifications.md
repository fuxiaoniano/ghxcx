# 微信群挂号通知：接入状态与上线门槛

> 此能力默认关闭。本文记录其安全边界；任何后续启用都必须重新完成真实发送端和目标群验收。

## 已落地（默认关闭）

- 小程序与公开留资页均以已保存的 `Appointment.landingPageId` 入队；公众号、小程序通知和回访转发仍走原链路。
- 独立 `wechat_group_*` 表保存发送账号、经稳定 ID 验证的群、页面路由、按挂号与群唯一的持久化任务和尝试记录。
- 新挂号入队失败不回滚已成功保存的挂号；30 秒补偿扫描处理漏建任务。群离线不会删除排队任务。
- 后台“小程序页 / 微信群挂号通知”可查看发送端、群、页面路由和脱敏任务记录；权限独立。
- **所有新路由默认停用，启用接口也会拒绝。没有任何个人微信自动发送端、群绑定、二维码或“成功回执”的假实现。**

## 为什么此版本不能启用真实发群

生产后端是 Linux，无 Windows 微信交互桌面。当前 Windows 工作机虽然安装微信 4.1.15.13，但没有可操作的窗口、专用已登录账号与两个测试群。wxauto 免费版文档仅列兼容到 4.1.8.107；其公开群列表返回名称，未证实能取得防重名误投所需的稳定群 ID。Plus 版需激活和适用许可，也未获提供或测试。公众号 OAuth 扫码不可代替个人微信登录。

## 启用前必须完成

1. 提供由业务控制的专用微信号、授权可用的 Windows 交互桌面（或经真实验证支持 Linux 的服务提供方），及两个测试群，其中一群含独立个人微信成员。不得提供微信密码。
2. 核实适配方案许可证、当前客户端版本；实测登录二维码、手机确认、掉线与重登、稳定群标识、向两群发文字、在各自群会话核对编号。群 ID 只能来自经测试的适配层，不能用群名称或本地伪造 ID。
3. 实现并测试鉴权内部接口、心跳、独立 Windows 发送端（不可运行于 Session 0）、领取租约、超时 UNKNOWN 回查、明确失败重试和独立接收端核验；在这之前保持启用接口拒绝。
4. 检查群内成员是否获授权查看挂号个人信息。手机号默认脱敏，完整手机号应独立授权并记录审计。
5. 用两个留资页测试两群及一页多群；关闭后台网页、断开发送端、重连、请求超时均需核对无漏发与无重复。独立群成员记录接收时间。
6. 执行迁移、构建、测试和现有公众号通知回归后，方可将经验证的发送端与后端一起部署启用。

## 生产轻量部署注意

迁移 `20261021000100_wechat_group_notification_foundation` 只新增表、枚举与索引，不修改旧通知表。后端仍运行在 Linux，页面可上线作为准备状态，但不能声称“自动发到微信群”已上线。不要将 Windows 微信桌面客户端放进 Linux 容器，也不要让 Session 0 服务执行桌面点击。内部密钥应由环境变量或系统秘密管理器注入，不能放入浏览器、仓库或普通日志。
