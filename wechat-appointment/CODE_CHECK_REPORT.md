# 代码与上线审查摘要

更新日期：2026-11-12

本文只概括当前代码基线和持续审查边界。逐次修改证据记录在 `AGENTS.md`，历史专项审查位于 `docs/`。

## 当前架构

- NestJS 服务端统一承载鉴权、权限、数据范围、挂号/网咨、通知、推广数据、腾讯广告集成、任务与审计。
- Prisma 管理 MySQL 模型和历史迁移；Redis 用于限流、锁、短期状态和任务协调。
- Vue 3 管理后台按路由懒加载；website 独立构建；原生微信小程序通过服务端 API 读取动态配置。
- Nginx 提供 HTTPS、静态资源和 API 反向代理；生产使用 Docker Compose 管理服务端、MySQL 和 Redis。

## 已建立的关键保护

- 服务端权限与成员/团队/推广账户数据范围校验，批量操作逐项检查。
- 手机号加密存储、哈希检索、默认脱敏、完整手机号独立授权和审计。
- 腾讯广告统一 Client、既有 Token/User Token、账户授权、限流、错误转换和脱敏日志。
- 创意创建区分平台受理、查询核验和最终确认；结果不明不盲目重建。
- 通知及关键异步流程使用持久化任务、条件领取、幂等和 UNKNOWN 状态保护。
- 实际转化成本与营销单元目标成本使用不同字段和来源，累计报表按时段快照覆盖。
- CORS、上传/导入限制、导出权限、生产 source map、依赖安全和限流均纳入测试与发布检查。

## 当前验证基线

最近完整审查已覆盖服务端 Lint、类型检查、构建、Jest、Prisma 校验，管理后台和 website 构建，小程序类型检查，以及关键业务的自动化回归。具体套件数量和当次结果以 `AGENTS.md` 最新记录为准，不能跨版本沿用旧数字。

每次发布仍需重新执行：

```bash
pnpm --dir server lint
pnpm --dir server typecheck
pnpm --dir server test
pnpm --dir server build
pnpm --dir admin build
pnpm --dir website build
pnpm --dir miniprogram typecheck
```

## 不能由代码检查替代的项目

- 腾讯接口存在不等于目标账户获得权限；真实账户能力必须按接口和对象回读验证。
- HTTP 200 或创意 ID 不等于腾讯创意最终创建成功；只有平台回读一致才可确认。
- 自动化通知 mock 不等于真实公众号或小程序模板消息已送达。
- 构建通过不等于全部手机浏览器、小程序真机和长数据视觉场景通过。
- schema validate 不等于生产迁移与恢复演练完成。

## 发布判断

代码可进入生产发布的最低条件：P0 清零、可安全修复的 P1 已处理、完整质量门禁通过、迁移和回滚方案可执行、外部未验证项明确且不会被伪装为成功。真实广告写操作、通知发送、生产数据删除和灾难恢复演练必须取得单独授权。

详细操作见 [CHECKLIST.md](CHECKLIST.md) 和 [DEPLOYMENT.md](DEPLOYMENT.md)。
