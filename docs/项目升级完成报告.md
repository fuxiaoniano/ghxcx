# 项目升级完成报告

**项目：** 口腔挂号小程序企业官方升级

**完成日期：** 2026-08-22

**实施方式：** 小步升级、旧接口冻结、统一后台、增量 migration、人工可回滚

## 1. 完成结论

项目已从原单一挂号落地页扩展为企业官方口腔医院小程序，新增首页、医生介绍、新版预约、推荐套餐和个人中心五栏导航。新增业务复用原小程序登录、用户、加密手机号、管理员、审计、通知和回访体系；医生预约与套餐申请统一写入原 `appointments` 表，未复制后台或用户体系。

旧小程序 `landing/success/appointments` 三个页面、旧预约 DTO、旧 `POST /api/appointments` 及旧用户认证文件在本次升级中没有修改；历史外部页面路径继续保留。

## 3. 新增功能

- 后台可管理首页轮播、跳转、广告、品牌配置和排序/启停。
- 后台可管理科室、科室项目、医生资料、推荐状态、医生多图和出诊排期。
- 医生列表支持科室筛选并一次展示全部结果，不分页。
- 医生详情展示头像、职称、擅长、简介、出诊、咨询和挂号；挂号入口自动携带并选中 `doctorId`。
- 新预约按“科室项目 → 医生 → 信息”三步完成，排期名额事务占用并防重复提交。
- 后台可管理套餐分类、套餐、价格、文字详情和多图排序；用户端只提交咨询申请，不支付。
- 个人中心包含旧挂号、医生预约、套餐申请、问诊说明、在线咨询、协议和客服入口。
- 未关注公众号时根据现有 `wechat_identities.subscribedOfficialAccount` 将“在线咨询/联系客服”统一导向公众号关注专页；专页使用微信原生 `<official-account>` 组件，个人资料接口只返回脱敏信息。

## 9. 部署升级步骤

1. 暂停后台内容写入，确认当前线上代码版本并备份应用与上传目录。
2. 对 MySQL 做全量备份；记录 `appointments/users/admin_users` 行数、表结构和索引。
3. 在预发布 MySQL 8 执行 `npx prisma migrate deploy`，核对旧记录 `type = LEGACY_REGISTRATION`。
4. 在预发布插入科室、项目、医生排期和套餐数据，完成新版预约、套餐申请、后台筛选与通知联调。
5. 演练 `rollback.sql`：先导出新业务数据，再回滚并核对旧表；生产不自动执行破坏性回滚。
6. 配置 `SERVER_BASE_URL`、`ENTERPRISE_ASSET_DIR=/app/uploads/enterprise-assets`，确认现有 `./uploads:/app/uploads` 持久卷可写且会备份。
7. 构建并发布后端；确认 `/docs` 中 `/api/enterprise` 和 `/api/admin/enterprise` 可见。
8. 构建并发布原 Vue 后台，为管理员分配新增权限，录入首页、科室、医生排期和套餐内容。
9. 在微信后台确认 request/download 合法域名、隐私保护指引、手机号能力、客服能力、小程序与公众号主体/开放平台关联。
10. 在小程序后台“设置 → 关注公众号”关联同主体公众号；用微信开发者工具和已关注/未关注真机账号回归旧深链、5 个 tab 页、关注页及客服会话，再提交小程序审核。
11. 先灰度观察新旧挂号、通知、回访和错误日志，再全量发布。

## 10. 风险与限制

- 当前环境没有生产数据库，无法证明生产异常数据、数据量和锁等待不会影响 migration；必须预发布演练。
- `rollback.sql` 会删除新业务结构，执行前必须导出新业务数据并由 DBA 审核。
- 微信 `open-type="contact"` 属于小程序客服能力；未关注入口使用平台原生 `<official-account>` 组件。该组件受小程序与公众号主体关联、后台配置及进入小程序的场景值限制，组件不可展示时页面会给出微信搜索公众号的降级提示，必须由真实账号真机验收。
- 当前内容图片存本地持久卷；多实例部署需要共享对象存储或共享文件卷。
- 管理后台构建产物单包较大，现阶段不影响功能，后续可独立做路由懒加载优化，不应与本次兼容升级混在一起。
- 医疗宣传、医生资质、价格、销量和套餐文案需由医院运营及合规人员审核后上线。

### 11.1 本轮修复

- 修复管理员 DTO 未接受 `HOME_MANAGE / DOCTOR_MANAGE / PACKAGE_MANAGE / APPOINTMENT_MANAGE`，导致成员保存或微信邀请失败的问题。
- 新增“满足任一内容管理权限”校验，首页、医生、套餐管理员均可使用同一个企业图片上传接口；各内容读取和写入继续按原管理员体系隔离。
- 医生管理改用企业模块只读医院接口，避免只拥有 `DOCTOR_MANAGE` 的成员因缺少 `MANAGE_CONFIGS` 而整页加载失败。
- 后台菜单和路由增加新权限可见性/访问控制；新版与旧版预约权限仍双向兼容。
- 企业图片上传保留经过校验的文件扩展名，并增加跨域、缓存响应头，避免扩展名缺失导致微信图片组件按二进制文件处理。
- 医生出诊日期和预约日期统一输出 `YYYY-MM-DD`，避免成功页显示完整 ISO 时间。
- 医生详情、套餐详情和个人中心的咨询/客服入口统一检查公众号关注状态；未关注时进入原生 `<official-account>` 关注专页。
- 套餐申请禁止选择过去日期；手机号补录增加 11 位格式前置校验；预约/套餐/医生详情增加缺少关键 ID 时的保护。
- 补齐 ESLint 9 flat config，恢复仓库 `pnpm --dir server run lint` 检查能力，并清理两个无效 import。
