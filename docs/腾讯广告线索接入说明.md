# 腾讯广告线索接入说明

本项目已支持“腾讯广告表单提交 -> 腾讯广告线索平台 API 推送 -> 本地管理后台接收并跟进”的完整接收链路。

## 本地准备

1. 在 `.env` 中配置以下变量：

   ```dotenv
   TENCENT_ADS_LEADS_TOKEN=与腾讯广告推送规则一致的Token
   TENCENT_ADS_LEADS_SECRET=与腾讯广告推送规则一致的密钥
   TENCENT_ADS_LEADS_SIGNATURE_TOLERANCE_SECONDS=300
   SERVER_BASE_URL=https://实际后端域名
   ```

2. 执行数据库迁移并重启后端：

   ```bash
   pnpm --filter wechat-appointment-server exec prisma migrate deploy
   pnpm --filter wechat-appointment-server run build
   ```

3. 登录管理后台，打开“腾讯广告线索”，确认页面显示“接收凭证已配置”。

## 腾讯广告平台配置

在线索管理平台进入“后台管理 -> 线索应用设置 -> API 回传数据 -> API 回传设置”，新增推送规则：

- 推送方式：推送（POST）
- 推送地址：`https://实际后端域名/api/tencent-ads/leads/push`
- Token：与 `TENCENT_ADS_LEADS_TOKEN` 一致
- 密钥：与 `TENCENT_ADS_LEADS_SECRET` 一致
- 标准字段：建议保留全部字段
- 表单字段：按广告表单实际字段添加
- 自定义字段：可按业务需要添加

保存后先点击“推送测试”。接口成功响应如下：

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "id": "本后台记录ID",
    "leads_id": "腾讯线索ID"
  }
}
```

测试成功后再启用腾讯侧推送规则。

## 接收与安全规则

- 接口支持腾讯广告推送使用的旧版三要素签名：`base64(token,timestamp,digest)`。
- `digest` 支持 SHA1 或 SHA256，计算内容为 `token.timestamp.secret`。
- 默认拒绝时间戳与服务器时间相差超过 300 秒的请求。
- `leads_id` 唯一；腾讯重试同一线索时执行幂等更新，不生成重复记录。
- 标准手机号使用 AES-256-GCM 加密保存，列表和详情默认只显示脱敏号码。
- 原始推送数据会对常见手机号、身份证字段进行脱敏后保存。
- `bundle`、`layer_form_content`、`custom_qa` 中的广告表单字段会在详情的“广告表单内容”区域展示。
- 查看完整手机号需要 `VIEW_FULL_PHONE` 权限，修改跟进状态需要 `MANAGE_APPOINTMENTS` 权限，操作会写入审计日志。

## 常见测试失败原因

- 返回 `2001`：服务端 Token 或密钥没有配置。
- 返回 `2002`：腾讯侧与服务端的 Token/密钥不一致、签名算法 Header 不正确，或服务器时间偏差过大。
- 返回 `2101`：推送内容缺少 `leads_id`。
- 返回 `1100`：数据库迁移未执行，或保存数据时数据库异常。

腾讯广告要求正式推送地址可被公网访问；本地开发地址只能用于代码和单元测试，不能直接填写到腾讯广告平台。
